# 技能

这个目录是**技能源**。启动后端时，它会被**镜像**到 `backend/.evaai/skills-view/`——也就是模型看到的
只读挂载点 `/skills`。改完技能要**重启后端**才生效（没有热加载）。

## 一个技能长什么样

```
skills/
└── 写周报/
    ├── SKILL.md          ← 必须有，入口
    └── templates/        ← 可选：附件（模板、参考文件、脚本）
        └── 周报.md
```

`SKILL.md` 以 YAML frontmatter 开头：

```markdown
---
name: 写周报
description: 把这一周做过的事整理成一份能直接发出去的周报。
---

正文：模型该照着做的步骤。
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | 是 | **必须与目录名逐字相同**。不一致的会被跳过并记警告。 |
| `description` | 是 | 一句话说清「什么时候该用它」。**它直接进提示词**，模型只凭这一句决定要不要读正文。 |

其余字段（`license` / `version` / `allowed-tools` 等）**会被忽略**——写了不报错，但也不生效。

## 它是怎么被用上的

1. 启动期扫描这个目录，逐个读 `SKILL.md` 的 frontmatter；
2. 通过校验的技能被镜像到 `/skills`，只有 `name` + `description` + 位置进提示词；
3. 模型判断某个技能跟当前请求相关时，**自己**用 `read_file` 打开 `/skills/<名>/SKILL.md` 读全文
   再照着做。

所以**正文的写法很重要**：它就是给模型看的操作手册，写清步骤、给判断标准，而不是写给人看的介绍。

## 目录名规则

允许中文，但**不能**含 `/`、`\`、`..`、空白或控制字符，也不能以点开头或结尾。名字会当路径段用。

## 写坏了会怎样

**启动日志里有一条警告，服务照常起，那个技能只是不生效**（不会进 `/skills`）。警告里会点名是哪个
目录、差在哪里——照着改就行。

技能是**可选内容**，所以它不像「工具配置写错就拒绝启动」那样严厉。但也不会静默跳过：目录明明在那
却不生效、而日志里一个字都没有，那种问题只能靠猜。
